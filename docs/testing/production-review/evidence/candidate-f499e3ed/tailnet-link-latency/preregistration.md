# Operator-only link timing

Use the retained real CLI built from the proposed feature. Verify binary and source fingerprints. Run in an isolated temporary HOME using the public key and verified fingerprint of a synthetic/disposable trusted Entanglement peer. Use a PATH- or config-selected local executable which supports precisely `status --json`, emits fixed valid online status for a single stable peer, and appends a timestamped call to a private file. There is no actual Tailscale daemon, network, scheduler work or compute submission. The subprocess implementation and fixture are part of the timing. The experiment measures the full operator CLI wall time on this host, including spawn, status parsing, any config transaction and normal process teardown. It is not a system Tailscale latency estimate or dispatch benchmark.

Run one independent unmeasured preflight pair, then twelve fresh copies of a trusted but unlinked profile. With each copy, invoke exactly the same command twice in succession: once to add the confirmed peer-to-node mapping, then once when that exact mapping already exists. Record all 24 timed wall durations, exit statuses, output, exact status call count per invocation, result configuration and idempotence checks; first-then-repeat ordering is intrinsic to this procedure. Stop on a nonzero command, invalid config, changed trust, duplicate mapping, or unexpected fixture argument. Report median, nearest-rank p95 and range per kind plus subprocess/query counts. No cross-platform or throughput/SLA claim. Source review will separately trace whether the operator command introduced any new daemon/scheduler callsite, listener or periodic work, and describe costs of the already-configured tailnet mapping.

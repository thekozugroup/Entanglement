# Naturally flaky Rust workspace feasibility

The existing distributed evidence runs the unmodified nine-crate `rust-random/rngs` workspace on two authenticated workers and compares 224 named outcomes with native Cargo. A separate purpose-built retry case verifies that failed-then-passed remains classified as flaky. The stricter evidence plan requires a naturally occurring upstream failure and excludes that fixture from satisfying the gate. No upstream test execution was started during this source review.

## Strongest documented case

`option::test::probability_defaults_to_0p5` in upstream Proptest commit `cb347889a0b8709ec241133d5492095069987383` draws 1,000 weighted options from the default entropy-seeded runner and passes only when the count is 451 through 549. The next commit switches its statistical checks to deterministic seeds and explicitly cites spurious failures. The earlier string-generator fixes from 2018 concern a single-crate snapshot. [Exact affected test](https://github.com/proptest-rs/proptest/blob/cb347889a0b8709ec241133d5492095069987383/proptest/src/option.rs) · [Upstream fix](https://github.com/proptest-rs/proptest/commit/2325e7ac887ab3c87ad19d1498c4349cfd7ec808)

An ideal binomial count gives an initial failure probability of 0.001730536 per invocation. Two thousand independent initial attempts followed by one independent retry after each failure give about 96.85% probability of at least one failed-then-passed transition under that model.

The exact two-crate snapshot cannot build for `wasm32-wasip2` unchanged in the available configuration. Prior default builds hit the host-process `wait-timeout` crate, which has no WASI implementation. Disabling fork and timeout through upstream features still encounters the application source’s non-Windows branch importing `std::os::unix::ffi::OsStringExt`. Rust's WASI standard library does not expose that Unix extension. Modern Proptest gained further Wasm support after the statistical test fix. The current Entanglement route also lacks a supported native tier-5 runner for the historical code. [Affected source branch](https://github.com/proptest-rs/proptest/blob/cb347889a0b8709ec241133d5492095069987383/proptest/src/arbitrary/_std/env.rs#L85) · [Later upstream Wasm change](https://github.com/proptest-rs/proptest/commit/fdc53faf031f374019ab15857043cf9ab9ad7a20)

## Other checked paths

- `getrandom` supports WASI and its upstream tests explicitly use OS-entropy statistical assertions. The source documents ideal false-failure probabilities near 2⁻⁹¹ and 2⁻⁹⁴, which preclude a practical finite witness campaign. [Upstream tests](https://github.com/rust-random/getrandom/blob/97a7d496d9570cc138abd3b8b79690c75a66927f/tests/mod.rs)
- `rand_distr` continuous and discrete statistical checks seed their generators explicitly, including the Cauchy mean and median test that acknowledges statistical uncertainty. The selected seeds make those outcomes reproducible. The earlier full `rand` 0.8.5 workspace attempt separately failed to build its `special` statistical-test dependency against WASI because `lgamma` is unavailable there. [Current Cauchy test](https://github.com/rust-random/rand_distr/blob/d65b9bbf991e56d8a097a35d934e6f93d9194ac0/src/cauchy.rs)
- Published futures flake fixes concern `thread::spawn` and ordering between threads, including the mpsc zero-capacity and oneshot examples. The same blocker applies to Pest's published `ring_async` fix. The current WASI harness cannot execute those threads. [Mpsc fix](https://github.com/rust-lang/futures-rs/commit/c7c51bd760124be2bd5f190d5168caeab1b9c421) · [Oneshot fix](https://github.com/rust-lang/futures-rs/commit/4eb9a18bfc696e620ac3c272b58b23eb0d1a688d) · [Pest fix](https://github.com/pest-parser/pest/commit/72b88dde5e9cee2607bde5f1915b2bd0e8ce8096)

## Conditional preregistration

1. Pin one naturally stochastic named upstream case, the full unchanged workspace and dependency lock, the supported target configuration, toolchain, signed harness hashes and exact Entanglement release before executing the campaign. Compile the entire workspace with the documented WASI features. Match its native and Wasm inventories and recorded ignores. A compile failure or missing test ends the campaign with no passing result.
2. Run the complete Cargo workspace once on the native reference and across two authenticated workers using the existing libtest and rustdoc runner. Report every non-target outcome and transport/protocol error. Compare deterministic cases by name and outcome.
3. For the Proptest candidate above, use a fixed 2,000-initial-attempt cohort in native commands and a separate fixed 2,000-initial-attempt cohort across the two workers. For the remote arm alternate the starting peer by trial number and retry the exact same test once on the other peer when it reports the expected Rust assertion failure. Keep entropy at each upstream invocation's default. Keep all observations and execute the declared cohort regardless of when the first transition occurs. Establish time and CPU ceilings before starting, and report an interrupted cohort as incomplete.
4. Report one exact selected-case `failed → passed` transition on distinct authenticated workers and its aggregate flaky label, supported by the expected Rust assertion trace and an independently observed native transition under the same source. Report every parse error, timeout and transport failure separately. If the fixed budget yields no transition, leave the gate unevidenced and publish the complete results.

The statistical retention criterion is practical for a compatible upstream test at this failure rate. The closest documented workspace found in this review fails the unmodified WASI build prerequisite. Other compatible statistical checks reviewed have deterministic seeds or impractically small failure rates. A new unchanged compatible candidate or the architecture's actual native tier-5 worker can resolve the current block.

## Independent source review of random draws and map ordering

This review used immutable upstream Rust sources and public fix descriptions. Its probability estimates are planning calculations. It produced no new test executions or gate credit.

- **Tantivy has a documented upstream flake in a nine-package workspace.** At `dabcaa58093a3f7f10e98a5a3b06cfe2370482f9`, `terms_aggs_hosts_and_tags_merge_on_mixed_order_request` requires two independently constructed two-key standard hash maps to yield different first keys. Under independent equiprobable first-key selections, each initial attempt has about a 50% chance of failure. Before checking the maps, the test creates and commits two indexes with background writer threads. The unchanged test requires native threading. Default workspace tests also depend on mmap and Proptest's native process support. [Affected test](https://github.com/quickwit-oss/tantivy/blob/dabcaa58093a3f7f10e98a5a3b06cfe2370482f9/src/aggregation/bucket/term_agg.rs) · [Writer implementation](https://github.com/quickwit-oss/tantivy/blob/dabcaa58093a3f7f10e98a5a3b06cfe2370482f9/src/indexer/index_writer.rs) · [Cargo configuration](https://github.com/quickwit-oss/tantivy/blob/dabcaa58093a3f7f10e98a5a3b06cfe2370482f9/Cargo.toml) · [Upstream fix](https://github.com/quickwit-oss/tantivy/pull/2723)
- **Tinyrand has a genuine unseeded assertion with low practical yield.** In the five-package workspace at `8dd18ddefc9b057304441d9a7c112ba36d988dfe`, `tinyrand_std::thread_local::tests::with_thread_local` requires the first clock-seeded 16-bit draw to be nonzero. Under independent uniform draws, this check alone fails once per 65,536 initial attempts on average. Allowing one retry on failure gives a 3.01% chance of at least one fail–pass in 2,000 initial attempts, or about 196,330 initial attempts for 95%. The other assertions compare wider outputs. Seed behavior and native/WASI suite parity remain unmeasured. [Test](https://github.com/obsidiandynamics/tinyrand/blob/8dd18ddefc9b057304441d9a7c112ba36d988dfe/tinyrand-std/src/thread_local/tests.rs) · [Clock source](https://github.com/obsidiandynamics/tinyrand/blob/8dd18ddefc9b057304441d9a7c112ba36d988dfe/tinyrand-std/src/clock_seed.rs) · [Workspace](https://github.com/obsidiandynamics/tinyrand/blob/8dd18ddefc9b057304441d9a7c112ba36d988dfe/Cargo.toml)
- **Two smaller libraries illustrate the remaining eligibility limits.** The `shuffle` 0.2.1 four-element permutation assertion always starts with `DummyRng(0)`. The `rv` 0.20.2 circular-distribution histogram test draws from the host-seeded RNG and rejects at a nominal 1% significance level, but its upstream Cargo manifest defines one package. A targeted search of public serde_json, serde_with, Schemars and RON issue histories yielded no corroborated map-order regression in a small unchanged WASI-compatible workspace. [Shuffle test](https://github.com/adambudziak/shuffle/blob/8e21811f1e7d47acfb79af56a214f2d6fa05135b/src/irs.rs) · [Distribution test](https://github.com/promised-ai/rv/blob/3a63db9182916c846a80ec94ff012741a0e78b01/src/dist/vonmises.rs) · [Distribution library manifest](https://github.com/promised-ai/rv/blob/3a63db9182916c846a80ec94ff012741a0e78b01/Cargo.toml)

# Conditional natural upstream flake protocol — draft

Recorded before any repeated stochastic trial, 2026-11-27. This protocol does not itself authorize starting a campaign: the eligibility and feasibility prerequisites below must be established and the reviewers must agree.

## Candidate and eligibility

Use unchanged `obsidiandynamics/tinyrand` commit `8dd18ddefc9b057304441d9a7c112ba36d988dfe`, all five upstream workspace members, pinned toolchain and explicitly recorded generated lockfile (upstream does not track its lock). Target the unmodified `tinyrand_std::thread_local::tests::with_thread_local` test through the normal libtest and existing distributed scheduler path. Identify the exact released Entanglement binary hashes, signed test artifact and upstream checkout, dependency closure, runner/sharder versions and source digests before measurement. Never change or select the clock, seed, code, test input, peer trust or worker results to create a failure.

Before any repeated trials, the full `cargo test --workspace` must compile and run on both native and WASI using recorded ordinary features. Compare the complete named test/ignore inventory and all deterministic results, correctly retaining `should_panic` behavior; report every compiler failure, excluded component, timeout and protocol error. Source and executable digests must match before and after. If full unchanged workspace, test selection, parity, two-worker execution over authenticated transport or storage/time limits cannot be established, stop; PERF-TEST remains unevidenced under the stricter plan. A single normal full-suite prerequisite execution is not a stochastic campaign.

## Prespecified cohort

Subject to those prerequisites and reviewers' agreement on feasible resource bounds, run exactly 262,144 initial invocations in each of the native and distributed arms. Complete both cohorts without stopping on a witness; no extension or adaptive threshold. Each invocation receives the upstream default wall-clock-derived seed. Alternate the initial selected remote peer by trial number, through the existing signed artifact and scheduler route. Record the actually selected peer identity authenticated by the transport; the test result itself is not claimed to be individually signed. On the test's actual Rust assertion failure only, immediately retry the same test once, with the same artifact and ordinary settings; on the remote arm, require the other authenticated peer and prove its identity. Record every initial and retry attempt, assertion file/line and captured failure and success outputs, native/remote labels, artifact digest, timing, runner exit/classification, and aggregate flaky status. The retry must follow the first failure and be associated with it by a unique trial ID.

Separate assertion failures from compile, protocol, worker, infrastructure, transport, timeout and parsing errors; preserve every error and case disposition with no silent omissions. Define fixed runtime, disk and memory ceilings before starting; record interruption or any missing attempt as incomplete, not a pass. Publish lossless machine-readable per-attempt data, raw logs, hashes, source/binary/peer identities, commands, environment and a reproducible independent verifier. The witness must show a native failure followed by a success and a remote failure followed by success on distinct authenticated workers on the same signed artifact. Do not claim a transition if only one arm is witnessed. Report all other outcomes and any natural flaky cases.

## Probability and limits

The first assertion rejects zero in the low 16 bits of the first Wyrand draw. The seed is `SystemTime::now()` in nanoseconds folded by XOR, not operating-system random entropy. Under a hypothetical independent uniform model, each arm has about 98.17% chance of at least one failed initial draw in 262,144 attempts and the chance of a qualifying retry is approximately 96.37% across both arms. This is not an observed probability: clock granularity, correlation, worker execution, truncation and time scheduling can change the real result. No seeding or clock intervention is permitted. A completed cohort without both independently evidenced transitions leaves the stricter gate unmet.

The frozen primary scorecard and existing production-release findings remain unchanged. One-host isolated workers do not establish physical-host deployment or other architecture performance gates.

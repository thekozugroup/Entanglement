# Tinyrand workspace qualification

The unmodified five-member Tinyrand 0.5.0 workspace compiled for both Linux and WASI. Native Cargo passed all 131 cases. The released two-worker runner passed 97 of 104 ordinary cases. The remaining seven use Rust's `#[should_panic]` and require matching an expected panic. Both authenticated workers returned a libtest summary of one ignored, zero passed and zero failed for each exact selection. The sharder recorded seven errors and preserved both attempts for each. The strict prerequisite of equal native and distributed dispositions failed. The repeated clock-seeded campaign did not start. [Native and remote comparison](qualification.json) · [Raw remote attempts](distributed.json.gz)

The native run passed all 27 doctests. Rustdoc for this edition builds a standalone command for each example. Each of those 27 commands returned exit 0 from the authenticated guest. The existing evidence driver expected a merged rustdoc test summary and returned an adapter error for each. The full distributed Cargo command exited 101. The verifier matches each nested guest result to the named doctest and retains the adapter failures. [Full distributed Cargo log](distributed.log.gz) · [Native Cargo log](native.log.gz)

The selected test `thread_local::tests::with_thread_local` passed once in each ordinary full suite. Its WASI component was also independently built from the same lockfile using the package selector. Both builds emitted SHA-256 `f8bfe9ed20b0b3888ead6bf595431c16c68ba5406c57f97b7cbaf7f9a8851024`. The test reads the current wall clock to initialize its generator. No clock or seed override was applied. The target test appears in the two-worker discovery and ran once on the selected worker. [Affected upstream test](https://github.com/obsidiandynamics/tinyrand/blob/8dd18ddefc9b057304441d9a7c112ba36d988dfe/tinyrand-std/src/thread_local/tests.rs)

## Reproduction

Pin upstream commit `8dd18ddefc9b057304441d9a7c112ba36d988dfe` and Rust 1.91.1 with the `wasm32-wasip2` target. Upstream ignores its root Cargo.lock. Restore the recorded dependency lock, SHA-256 `74dc28149c697175a17dac75d7a48bef42790ebacfb2066dea641ede2c075929`, to that root. These runs used the upstream default features, `CARGO_BUILD_JOBS=2`, `CARGO_INCREMENTAL=0`, and `CARGO_PROFILE_DEV_DEBUG=0`. The full native command was `cargo +1.91.1 test --offline --locked --workspace`. [Workspace](https://github.com/obsidiandynamics/tinyrand/blob/8dd18ddefc9b057304441d9a7c112ba36d988dfe/Cargo.toml) · [Pinned lockfile](Cargo.lock.gz)

For the distributed run, collect the workspace package identifiers with `cargo +1.91.1 metadata --offline --locked --no-deps --format-version=1` and collect test artifacts with `cargo +1.91.1 test --offline --locked --workspace --target wasm32-wasip2 --no-run --message-format=json-render-diagnostics`. Supply both resulting files to the existing driver using its `--metadata` and `--wasm-artifacts` flags. Its `--root`, `--workspace`, `--binaries`, `--out` and `--cargo-log` arguments identify the release checkout, unchanged upstream checkout, verified release executables and two outputs. It signs and loads each artifact on two separately paired loopback QUIC workers and sets Cargo's target runner. Execute `python3 verify-qualification.py` in this directory to recompute the stored qualification JSON. [Cargo runner](../../candidate-864ae27b/distributed-rust-workspace/dispatch-cargo-workspace.py) · [Verifier](verify-qualification.py)

The candidate source SHA-256 was `9cae32b67ebd4784779d1c37cd9cea5efc1a640fdfd71fca9a67dda8d9c777ab` before and after the run. The CLI and daemon digests recorded in the remote report match the verified archive and its retained extracted executables. The selected suite also failed to compile with `RUSTFLAGS=-Cpanic=unwind` against the stock WASI toolchain, which reported that its `panic_unwind` crate does not have the unwind panic strategy. [Archive manifest](../linux-archive.json) · [Unwind build diagnostic](unwind.log.gz)

The upstream history check traversed 78 commits reachable from the fetched Git refs. The thread-local assertion existed in 39 of those commits, beginning with `793ceac5b8328f963f5939ef5a33bbc443129faa`. All 39 already had the unconditional `#[should_panic(expected="zero limit")]` on `zero_lim_64`. That check entered the workspace before the selected test.

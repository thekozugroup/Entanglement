# Native agent-host readiness

MAX-1 through MAX-3 require a loaded tier-5 `agent-host` and a 5→3 reduction. MAX-1 requires the affected list in stdout and a default unload-and-disable decision. MAX-2 requires the forced affected list in stderr and one `ENTANGLE-W0214` event per affected plugin. MAX-3 requires Cancel to restore ceiling 5 in the file and record `ENTANGLE-I0216`. [Acceptance criteria](../../../../../architecture.md#15-acceptance-criteria-phase-1-deliverables-written-as-testable-contracts)

The optimized Linux release rejects a tier-5 Wasm manifest before signing. It authenticates a valid tier-5 native package and refuses to register it at ceiling 5. At ceiling 3 the same package receives `ENTANGLE-E0043`. The 5→3 PTY and forced commands apply with an empty affected set and the signed tier-3 Wasm component still serves requests. The existing 5→2 test exercises the nonempty affected list, default, cancellation, per-plugin audit, stale review and disabled-on-restart behavior. These results are policy conformance evidence. The loaded native agent-host prerequisite stays open. [Exact-source test receipt](receipt.json)

## Implementation boundaries

- The runtime registry holds Wasm compute, streaming and metric components. Native admission stops before broker registration and there is no native child lifecycle. The architecture specifies Cap’n Proto IPC over a Unix socket for subprocess plugins. The tier transaction already reviews the loaded registry, drains invocations and persists disable decisions. A supervisor needs explicit child-tree ownership and a way to confirm shutdown before reporting unload success. [Native admission](../../../../../../crates/entangle-runtime/src/kernel.rs#L294) · [Tier transaction](../../../../../../crates/entangle-runtime/src/kernel/tier_change.rs#L79)
- Claude Code, Codex and OpenCode have scaffolded configuration adapters. `AgentSession` currently patches the active config file in place and attempts to restore an in-memory snapshot on drop. The adapters insert one gateway entry and leave other configured servers in place. The gateway validates bind configuration and returns `E0620` on start. A production path needs private, per-session files that leave the original config untouched, a bounded authenticated gateway, approved tool routing, and before/after audit events. [Session code](../../../../../../crates/entangle-agent-host/src/session.rs#L26) · [Gateway code](../../../../../../crates/entangle-agent-host/src/gateway.rs#L151)
- Shell wrappers give warning-only feedback. The supported inference adapter streams from an operator-owned local model server and uses the live tier-5 admission lease. The operator separately controls that server's process permissions. [Wrapper code](../../../../../../crates/entangle-cli/src/cmd/wrapper.rs#L105) · [Inference service](../../../../../operations.md#streaming-inference-from-a-worker)

## Validation scope for a native supervisor

Use an authorized Linux host or VM where sandbox enforcement can be exercised. In the managed review process, a Landlock ABI query returned `ENOSYS` and bubblewrap's benign user namespace launch failed writing the UID map on a read-only filesystem. The standard systemd daemon service also restricts namespace creation, visible devices and control-group modification. Keep that service hardened and evaluate any supervisor as a separately scoped component. Linux file isolation, process limits and network policy each require enforcement tests. Landlock TCP rules alone express port restrictions. Host-specific egress needs a separately enforced network policy. macOS sandbox behavior and native Windows support require their own validation. The three MAX scenarios can run on one supported host with a genuine loaded agent-host. [Sandbox probe](../../../../../../crates/entangle-runtime/src/os_sandbox.rs#L56) · [Daemon unit](../../../../../../packaging/entangled.service#L46)

Start with a first-party supervisor test harness on the authorized host, using a fixed, harmless executable and a read-only WASI tool behind a local gateway. Prove publisher and artifact binding, per-session operator consent, a private configuration, capability-denial behavior, child-tree cleanup, and tier-change audit events. Keep command paths, arguments and credentials outside job input. Then validate one pinned real agent integration with independent security review. Obtain separate consent if that integration test uses live vendor credentials. Run the literal MAX cases after the agent-host is loaded through the normal production admission path.

# Independent acceptance plan: distributed Rust-test source iteration

Preregistered 2026-11-27 before candidate execution. This document describes test design, not a test result or authorization to change the fixed project rubric. Scope is the actual candidate source and ordinary supported commands. No product edits, GitHub Actions, publication, synthetic credentials, seed manipulation or unbounded stochastic search. Record full commit and source ID, commands, UTC times, toolchain/target/features, source before/after, hashes of binaries, packages, runners and all raw logs; record per-test and per-peer outcomes and retain failures. Execution is local and directly operated unless a separately authorized physical host is supplied. Tests below use benign disposable fixtures and identities.

## Binary acceptance criteria for the change

Each numbered item is a separate pass/fail/not-evidenced item: a pass requires every applicable assertion and an actual source-bound execution; a counterexample is fail; a missing fixture/target/receipt is not evidenced. No averages or partial points. Tests may use deterministic controlled sequences for implementation conformance, while naturally flaky upstream-suite evidence is a separate release claim. Existing baselines and receipts are not rerun or inherited as proof for new source. If a proposed mode is absent, report absent; do not silently substitute a different mode.

1. **Truthful libtest outcomes.** Drive the real parser/runner with ordinary libtest observations and adversarial but non-executable text/protocol fixtures: one exact selected passing test, actual assertion failure, expected-panic passing test on a runtime that truly supports it, listed ignore and target-reported ignore, no matches, more than one test selected, malformed/truncated or duplicate/contradictory summary, nonzero or trapped process without a Rust assertion, actual timeout/transport error. Assert exit status, report categories, counts, full attempt order and raw diagnostics; no abort, ignored, timeout, unknown exit or invalid summary may become a pass. An infrastructure error must not be called a test failure or flake. Verify genuine WASI `should_panic` target-ignored cases stay ignored and native passed cases remain distinguishable; no claiming they are equivalent. Verify filtering, exact names, explicit include-ignored behavior and empty-attempt listed ignores. Reject identity or response mismatches. Include both real and unit-level tests so a mocked parser is not the sole evidence.
2. **Native selection and isolation.** If native execution is implemented, package and run an actual benign native libtest on the supported OS and a signed WASI suite, use the normal selection entry point and prove requested executor/runtime corresponds to what ran. Include explicit opt-in, disabled/unavailable native runtime, trust/policy/capability refusal, no silent fallback to local, wrong platform or different binary, missing/invalid artifact and timeout. Verify native fixture command, executable digest, named-test inventory, exact outputs and cleanup; check peer chosen from authenticated connection and independently observable execution. Test actual native `should_panic` pass and ordinary failure distinctly. If native host execution is absent or cannot be demonstrated, this criterion is not evidenced; a Wasm surrogate cannot satisfy it. Scope OS/architecture and agent sandboxing claims to what was actually verified.
3. **Signed artifact agreement through discovery and execution.** On at least two actual paired daemon processes, use two separately signed benign packages with the same claimed logical plugin ID/version but distinct executable or manifest contents; verify genuine signatures and publisher authorization as the documented setup requires. Workers serving different executable content must fail discovery as a mismatch *before any test body executes*, even if libtest names/ignores match. Match full authenticated executable/package identity to the selected peer during discovery, every exact run and every retry; include a controlled package replacement/unload/reload between discovery and run, and between failure and retry. Any changed/missing/untrusted/revoked artifact or identity is explicit failure/error with no result credited and no guest side effects. Matching package across workers yields positive exact-output controls and distinct peer attribution. Independently check package bytes and identity; transport-authenticated results must not be described as detached-signed unless they actually are. Test no-manual-retry and concurrent swaps, and ensure the pinned package identity is checked at the execution boundary, not only in a coordinator cache.
4. **Retry semantics, count and attribution.** Test genuine fail→pass across two authenticated workers as flaky with preserved first assertion, identity, artifact digest and both attempts. Also fail→fail, fail→ignore, fail→ignore→pass, transport-error→pass, wrong artifact→pass attempt, ignored-first, exhausted budget and one-peer behavior. Exactly the configured attempts are permitted, and no attempt is silently lost; invalid identity/artifact stays an error and must not be transmuted into a pass/flaky by a retry. Distinguish test failures from infrastructure errors even if both are retried. Verify aggregate totals, CLI exit status and normal existing behavior; if prior transport-error→pass semantics are intentionally preserved, report the earlier error visibly and document the policy instead of calling it a flake. A controlled failure fixture proves the mechanism only, not a naturally occurring upstream flake.
5. **Work-conserving scheduling.** Use deterministic synchronization/barriers and at least two independently observable workers: block a long selected test on worker A, allow worker B's shorter test to finish, and prove B starts the next eligible queued test before A is released. Verify no concurrent double execution of one attempt, no dispatch to a peer that is busy/untrusted/over its limit, no extra concurrency beyond worker limits, and retry failure goes to an eligible permitted alternate worker without starving queued work. Release the barrier, verify every named test exactly once per intended attempt, categories, attribution, cleanup and normal report order/semantics. Include one-worker, unequal test durations, all busy, worker failure and zero-runnable tests. Evidence should use monotonic event ordering plus peer invocation counters rather than a flaky wall-clock speedup threshold. A passing synthetic queue test alone does not establish physical performance.
6. **JSON→JUnit integration if delivered.** Run the actual optional standalone converter entry point on an authentic generated report, then independently parse its XML with standard library. Match suite/test names, counts, elapsed units, escaping and Unicode; preserve pass, fail, ignored/skipped, infrastructure error and flaky retry history/diagnostics with truthful status semantics. Check multiple suites, empty suite, malformed/missing fields, oversized or truncated input, invalid XML control characters, path/output error and file replacement. An invalid report must fail without emitting a falsely successful JUnit document. Round-trip semantic comparison must not rely only on XML validity. Show both native JSON remains authoritative and converter does not rerun or reclassify tests. If not delivered, mark optional criterion not applicable, not a project pass.

## Genuine workspace evidence and strict scoring

Run the selected real unchanged multi-package upstream workspace using its documented `cargo test --workspace` command, pinned revision and lock, and actual candidate's signed artifacts on two authenticated remote worker processes. Compare the complete native and distributed inventories and all named dispositions, including documentation tests and target-specific ignores; preserve all compiler/target exclusions and differentiate pass→ignore from parity. Record actual peer for each selected attempt, full scheduler and output evidence. A separate signed deterministic retry fixture can demonstrate the literal rubric's mechanism but cannot satisfy the stricter predeclared natural-flake requirement. For strict PERF-TEST, require a genuinely naturally occurring assertion failure then successful retry on an authenticated different worker, same unmodified artifact and normal input; pin finite campaign and time/storage limits before trials and keep all initial failures, repeats, errors, and non-target suite outcomes. No forced failure, altered entropy/clock, unreported runs, test modification, or retrospectively selected case. No witness = not evidenced, never infer one probabilistically. No task requires running a stochastic campaign until a separate fully specified protocol is agreed.

The project-wide adjudication remains exactly `docs/testing/production-review/rubric-v1.json` plus the separate `final-evidence-plan.md` strict view: all 57 criteria and all six metric denominators, >95 threshold, hard failures, no changed weights and no averages that hide blockers. Each claimed status requires independently reviewed current-commit source-bound receipts and exact hashes; default missing proof to not_evidenced. Record any real failure independently of missing external evidence. Do not mutate previous ledgers or carry observations forward on the basis of matching names or identical code. Distinguish test fixtures, ordinary local QEMU/container results, independent physical hosts, real production signing/governance and forbidden hosted CI. Use the preexisting local 9-crate, Tinyrand, proptest, Rand/getrandom and documented flake feasibility receipts to avoid repeated exploratory work; current Tinyrand has seven native-pass/WASI-ignore cases and is not equivalent.

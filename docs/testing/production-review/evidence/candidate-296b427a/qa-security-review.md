Scope is the changed libtest package pinning, scheduler retry and selector logic, structured remote error propagation and JSON-to-JUnit conversion, with a local publisher-containment rehearsal. This supplements the earlier review; it is not a general external audit, host attestation or production key-custody assessment.

`Kernel` verifies artifact and exact manifest against a trusted key and publisher binding before it constructs the libtest identity. The host adapter compares the expected digest pair before setting up the WASI invocation and emits its own identity alongside captured stdout and stderr. The runner pins discovery, exact runs and retries and treats a mismatch, authorization failure, missing loaded plugin, unexpected chosen peer or absent identity as an error. The response guarantee applies to operator-approved signed `wasi:cli/command@0.2.0` libtest packages using that host adapter. Arbitrary unrelated guest ABIs can return opaque guest-selected JSON; neither a cryptographically attested host nor guest-proof transcript provenance is asserted.

The runner permits at most one active call per selected worker, assigns a freed worker queued eligible work, retains retry attempts, and distinguishes runtime ignore, failure and infrastructure error. An earlier infrastructure error followed by a successful retry retains the error in attempt history but is classified passed under the existing retry policy. Rust libtest output is a text protocol: an ambiguous duplicated complete frame fails closed, and an arbitrarily fabricated transcript cannot be authenticated from its text alone. Legitimate multiline ignore reasons cannot be reliably distinguished from appended text. The JUnit converter validates report/attempt consistency, escapes XML and preserves the attempt history; it is a presentation adapter, not proof of guest or host provenance.

Fresh [live identity controls](rust-sharder-integration/identity-first.json) exercised independently signed same-ID artifact and manifest differences, mismatch before exact execution and retry, admitted-run/unload ordering, subsequent replacement, legacy upgrade behavior and revocation/unload paths on paired Linux daemons. Removing a publisher key alone does not retroactively unload an already admitted package; the test reports that behavior explicitly. Fresh [Python runner checks](qa-runner-python.json) and [converter checks](qa-junit-python.json) passed; three source-bound workspace runs are recorded separately.

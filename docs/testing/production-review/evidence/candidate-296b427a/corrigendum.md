# Preregistered corrigendum: native selector oracle

Recorded before integrated candidate execution on 2026-11-27. The original acceptance.md SHA-256 `764ba58d7873b3c4bc2ed127c1dca778f05e42716afa0ac1b30cb0d2466c775e` remains unchanged.

Criterion 2 of the original plan is replaced **for this iteration's binary acceptance** by the following selector criterion. "Native" means an ordinary real native Rust libtest used as an independent behavior oracle; it does not request native execution on remote peers.

**2. Native selection oracle.** Compile and run the same benign Rust test source as a real host-native libtest and as the signed WASI component. Through the candidate's normal documented entry point, compare selected names and named dispositions against the native harness for one substring filter, exact-name selection, repeatable include filters with OR semantics, repeatable skip filters, matching/nonmatching and overlapping include/skip, default ignored tests, explicit `--ignored` and `--include-ignored` semantics where supported, and zero-match. Verify filtered counts, aggregate statuses, report output and exit status; no dropped or duplicate tests. Run names with module separators and substring collisions so exact and substring behavior are distinguishable. Compare true native `#[should_panic]` pass with a target-reported WASI ignore as two different dispositions; explicitly report any target-specific exclusions, never normalize them to parity. Test one source-defined actual assertion failure and its captured output, and confirm existing behavior for previous documented flags. Require both unit-level cases and real signed two-worker end-to-end output against native to pass. The exact invocation and native libtest reference are recorded before measurement.

Remote native execution remains a separately unfulfilled global/optional capability; its absence does not fail this selector criterion and must not be advertised as implemented. It may be relevant to an architecture-level tier-5 requirement, which remains independently adjudicated under the unchanged 57-gate rubric.

For optional JSON→JUnit conversion, an O(report-size) implementation may be acceptable for a finite single file: feed a large *real* report of documented byte/entry size, check complete semantic totals and bounded completion, and report measured memory where available without inventing a streaming requirement. Oversized or partial RPC strings remain negative tests only when those strings are relevant to the actual transport/entry point. Missing, malformed, truncated or invalid inputs must not silently yield a successful XML report. The full fixed rubric and no-synthetic-flake boundary in acceptance.md are unchanged.

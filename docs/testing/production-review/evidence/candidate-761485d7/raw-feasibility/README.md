# Camera RAW and dehaze feasibility

A private native compatibility probe opened and unpacked a genuine Kodak DC50 camera RAW using LibRaw 0.21.4. The 92,675-byte KDC produced a 768 × 512 raster, and ImageMagick reported 16-bit sRGB output. The fixture has SHA-256 `37e290dbd0053f00e508d02a6b3a2a990432dad1eb74c40a52ca899f0f225ecc`. Rawsamples.ch supplied this image under CC BY-NC-SA 4.0. The pinned rawpy mirror provides the image-specific attribution. This evidence publishes only numeric metadata, links and the probe. Commercial benchmarking or redistribution requires suitable image rights. [Fixture revision](https://github.com/letmaik/rawpy/blob/2705f5b223c162c3cbc48474fe1a01c3cf09fa4f/test/RAW_KODAK_DC50_%C3%A9.KDC) · [Sample-specific license](https://github.com/letmaik/rawpy/blob/2705f5b223c162c3cbc48474fe1a01c3cf09fa4f/test/README.txt) · [Probe results](probe.json)

A separate generated linear RGB scene has known haze, clear colors and atmospheric light. A dark-channel prior implementation estimated the correct atmospheric light and reduced mean absolute error from 0.22315 to 0.01800 over 8,192 pixels. It used a 15 × 15 minimum filter, an atmospheric candidate fraction of 0.001, a haze retention setting of 0.95 and a minimum transmission of 0.10. This checks the dehaze arithmetic for one deliberately tractable scene. Natural-image quality, detailed reconstruction in sky regions, color management and the final application still need validation. [Probe source](probe.py) · [Dark-channel prior paper](https://doi.org/10.1109/TPAMI.2010.168)

The following private invocation uses Debian's packaged NumPy, SciPy, LibRaw and ImageMagick. The probe checks fixture length, hash and dimensions before unpacking. It keeps the sample under a 1 GiB process address-space limit, with a six-second CPU limit and a ten-second wall limit. The generated test uses no sample-derived pixels.

```sh

    timeout 10s prlimit --as=1073741824:1073741824 --cpu=6:6 \
    /usr/bin/python3 probe.py /path/to/RAW_KODAK_DC50_é.KDC
```

## Implementable compatibility scope

The current production guest implements PNG/JPEG resizing. A signed Tier-1 guest can expose an explicit RAW input contract through the same byte-oriented ABI. Two distinct decoder scopes are technically plausible.

- An initial DNG implementation can accept uncompressed single-plane Bayer sensor IFDs with specified bit depths and a short allowlist of CFA arrangements. It must validate DNGVersion, photometric interpretation, white/black levels, CFA tags, color and white-balance metadata, active area/orientation, and all strip or tile ranges before allocation. It needs explicit handling or rejection for LinearRaw, unknown opcodes, compressed payloads and preview-only IFDs. A TIFF header or a DNG filename alone cannot establish those properties. The proprietary KDC probe provides no DNG coverage. That scope needs an independently authorized real DNG plus synthetic cases with known sensor/linear-color truth. [Adobe DNG specification and resources](https://helpx.adobe.com/camera-raw/digital-negative.html)
- Kodak DC50 compatibility requires a model-specific RADC decoder, black/white normalization and the correct camera profile. A candidate could port a bounded memory-input decoder, demosaic and apply a declared linear color pipeline before dark-channel estimation. LibRaw offers a native independent reference. The rawler repository carries a DC50 implementation under LGPL-2.1 and dependencies including Rayon, dynamic loading and memory mapping. A WASI build, licensed distribution and camera color agreement require separate validation. [Model-specific decoder](https://github.com/dnglab/dnglab/blob/4c64720653976343479a883bfd1e6066151ac093/rawler/src/decoders/kdc.rs#L93) · [Dependency and license declarations](https://github.com/dnglab/dnglab/blob/4c64720653976343479a883bfd1e6066151ac093/rawler/Cargo.toml)

An image can fit its compressed input limit while exhausting the guest during demosaic, color transform or transmission filtering. Bound decoded dimensions, checked byte counts and peak working buffers as well as compressed input and output. The released remote one-shot worker caps each payload at 16 MiB by default, the transport frame cap adds 64 KiB and the guest store defaults to 256 MiB. Larger inputs require a separately validated authenticated blob or chunk transport, or another explicitly bounded delivery design. ## Workload B acceptance

Use one signed plugin and identical parameters for an independent native color/dehaze reference, a single-desktop run, and a three-desktop mesh run. Pin a manifest of camera originals, hashes and reuse rights. Validate each output against predeclared per-channel or exact comparisons in the same output color encoding. Log peer IDs, per-route bytes and bandwidth, output checks, failures and retries. Place the submitter outside the set of eligible workers for remote-only tests, permit just the trusted workers, and verify actual worker receipts. Measure elapsed time including all input and output transfers and completion checks. Keep caches, concurrency and hardware constraints documented. Spectrum of camera formats, output accuracy and slow-link placement need separate checks.

Architecture §7.0 requires 8,000 RAW photos, three physical desktops, bandwidth-aware placement and a 10× wall-clock speedup against a single machine. The host checks above establish a bounded native compatibility starting point. The released guest, licensed corpus, hardware and throughput result required for the full gate remain outstanding.

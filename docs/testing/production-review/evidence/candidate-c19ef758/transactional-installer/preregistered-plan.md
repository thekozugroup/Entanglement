Prepared 2026-11-27 before either proposed repair. This is a plan, not a passing test or release authorization. The current primary source and rubric results remain unchanged. No GitHub Actions, public upload, publication or production signing will be performed. All execution is local and source-bound; retain every setup failure, assertion and receipt. Upon freeze, record exact commit, source ID before/after, toolchain, OS/architecture, commands, timestamps, environment overrides, hashes of runner, exact install script, official packaging entry point, all input/output binaries, archives, sidecars and raw logs. Separately record process exits and independently validate outputs. ## Genuine binaries and installation

Use two genuine existing optimized same-target x86-64 GNU/Linux archives, freeze-bound manifests, and verified sha256/BLAKE3 sidecars: Jammy-compatible `a0926c6ef347-ubuntu22` (`entangle`/`entangled` require GLIBC_2.34) and canonical `a0926c6ef347` (requires GLIBC_2.39). Both currently declare v0.1.0. Inspect their independently computed hashes and symbol requirements; do not alter ELF contents or relabel version output to manufacture failure. Use the actual candidate `scripts/install.sh` as invoked by a user, actual platform autodetection, the normal production archive layout and the project's local-only HTTPS URL fixture. Download adapter serves exactly the specified archive and its sidecar and records URLs; no remote requests. Use unprivileged fresh Ubuntu 22.04 (glibc 2.35) and Ubuntu 24.04 or Debian 13 (glibc >=2.39) userlands on the one available host, record actual image IDs, UID, libc and container networking. Never count these as independent hardware or macOS evidence.

1. On Jammy install both compatible release binaries to a clean prefix. Hash both files, prove both `--version` work, and start the actual installed daemon and query it through the installed CLI over local UDS; stop it cleanly. Exercise an actually signed ordinary plugin with explicit disposable publisher trust and an independently checked nonce when practical. Record both executable hashes and status, not just CLI success.
2. With that working pair present, offer the genuine incompatible canonical archive as an upgrade using `--force` (the two genuine archives have the same version); its valid checksum must pass. Independently prove the canonical binaries themselves fail on Jammy due to GLIBC_2.39. Installer must fail nonzero and leave *both* original files byte-identical, runnable, and still able to start/query daemon. Record output and before/after digests; reject a mixed pair, a success exit, or removal of either binary. This verifies the completed failed invocation, not power-loss atomicity.
3. On the newer distro, offer the same canonical archive under `--force` and require successful install, both byte-identical to archive, both runnable and actual installed daemon/CLI UDS functionality. Confirm the compatible pair also runs there. This distinguishes an incompatible artifact from a generally broken artifact.
4. Without `--force`, make deliberately partial states using real installed artifacts: (a) CLI present and daemon missing; (b) CLI present and daemon incompatible/unexecutable for host; (c) daemon present and CLI missing; (d) one binary is from a different build of the same version. Installer must not claim an already-complete install based on CLI version alone; with the compatible archive available it must repair both to matching candidate archive hashes, yield successful exit and run both commands. If indistinguishable same-version-but-foreign bytes cannot be identified without a persisted trusted digest, document exact supported contract rather than inventing a replacement requirement.
5. Exercise malformed/missing checksum, checksum mismatch, missing archive member and unwritable destination or controlled second-copy/rename failure. Assert explicit failure and byte-identical preservation of both original working files, no new executable on PATH and clean temporary files where supported. Use an exact local fixture with deliberately malformed archive/sidecar only for these negative controls; do not mistake their checksum agreement for authenticity. Check no untrusted binary is run before integrity verification. Run interrupted-update recovery only if the implementation explicitly promises it; do not infer crash-safe two-file atomicity from an ordinary successful rollback.
6. Keep existing fresh-install, version-equal no-op when both components are genuinely valid, `--force`, no-sudo, dry-run and portable hash-tool paths. Record exit codes and actual post-state. Verify only the two targeted command files and preserve unrelated files/permissions. The shell installer checks a digest; its local sidecar is not a publisher signature or a production release proof.

## Canonical native archive determinism

Invoke the same documented packaging command/helper actually used by the release workflow, locally and directly. Do not simulate a workflow, invoke GitHub Actions, or reimplement the production packager in the oracle. Fix one explicit source revision, target, version, complete whitelist of regular-file bytes, and *identical* two optimized ELF input digests for all packaging trials. Build equivalent fresh staging trees under unrelated path names, create members in reversed and shuffled order, set different file/directory mtimes and umasks, and use distinct ownership/UID/GID where safely feasible. Record actual pre-packaging stat metadata; unsupported ownership variation is a limitation rather than a claimed case. Run the canonical packager at least twice per variation, with clean output dirs, in differing local timezone/locale contexts where available. Verify SHA-256 and BLAKE3 independently; every resulting `.tar.gz` and both digest values must match byte-for-byte. Confirm changed actual member content changes the archive digest, and missing/extra required files fail as specified instead of silently producing a partial artifact.

As an input-boundary negative, provide a staged expected member as a symlink to an out-of-tree sentinel and a hardlink or special file when supported. The packager must reject the non-regular/escaping input or demonstrably copy only the explicitly permitted regular bytes under the published policy; it must never package sentinel contents as a named release member. Independently test a duplicate or path-traversing tar member only if the implementation accepts an input archive; do not create exploit payloads for a helper that only accepts files. Destination symlink and collision behavior must not clobber an unrelated sentinel. Record actual policy and outcomes.

Independently read each resulting gzip/tar stream using Python's standard-library parsers: require a fixed allowed top-level release name, exactly the expected two executables and four documentation/license files (and only explicitly declared directory entries), unique normalized relative names, regular files, no symlinks/hardlinks, absolute or `..` paths, devices or unexpected entries. Verify each extracted content digest and executable/document modes against the intended fixed inputs. Inspect and compare actual uid/gid/uname/gname, mtime, ordering, tar extension/PAX records and gzip header fields; candidate output must derive their canonical values from the release policy, not arbitrary staged metadata. Do not use extraction as the metadata oracle. Validate sidecars against the independently hashed emitted archive and invoke the existing checksum verifier; separate normal signature verification must reject missing Sigstore/publisher proofs on unsigned local archives.

Run candidate-built packaging helper tests on the available GNU/Linux host and, where genuine tool support is present, in the two specified Linux userlands. Any extra implementation-specific tool dependency or missing host shell is reported as a limitation, not skipped silently. Validate release workflow references the exact same helper using source inspection only. Independently apply the verified archive to the installer positive and incompatible/rollback paths above. This demonstrates same-source, *same-ELF* byte-stable packaging under varied staging metadata; it does not by itself show deterministic Rust compiler output, same-source rebuild reproducibility on independent hosts, macOS artifact parity, publisher signatures, provenance, production governance, or safe publication. To establish rebuilt-binary reproducibility separately, make two genuinely clean locked builds under declared toolchain and compare ELF hashes before packaging; if either differs, report it and do not conflate packaging determinism with build determinism.

## What changed for operators

The old POSIX installer could overwrite a working CLI and daemon on Ubuntu 22.04 with a checksum-valid pair that required glibc 2.39. Its version shortcut could also report success with the daemon missing. The installer now verifies the downloaded checksum, stages both executables inside the destination filesystem and runs each staged executable to check its name and requested version. It reserves the destination during updates and restores prior files on a caught installation failure. Both installed executables must pass their version checks before a same-version invocation can exit early. An uncatchable interruption between renames can require manual recovery. Operators can use `--force` to replace a runnable pair carrying the same version string. [Installation guide](../../../../install.md) · [Independent review](successor-security-review.md) · [Concurrent installation](installer-active-reservation.json)

The release workflow now invokes the same native packager available to operators locally. It records the tag commit's timestamp in gzip and USTAR, normalizes member order, modes and ownership, and publishes SHA-256 and BLAKE3 sidecars beside the archive. The previous packager produced different archives from identical inputs when staging metadata changed. The Linux release build used the repository's locked release command and an existing Cargo cache. Its CLI and daemon match the previous reviewed binaries byte for byte. All four release documents also have the same hashes.

## Installer transaction

- **Interrupted or incompatible upgrade — corrected.** Both candidate executables run their exact requested `--version` from private, destination-filesystem staging after SHA-256 verification. The installer snapshots the previous entries before the first rename. A failed second rename or a handled HUP, INT or TERM invokes rollback. Ordinary failure when first installing removes any new partial pair. A rollback failure retains the recovery files and tells the operator where they are. The independent test run covered missing and unusable daemons, partial first installs, second-rename failures, TERM during publication, successful repair and rollback failure. [Installer](../../../../../scripts/install.sh) · [Conformance log](defensive-scope.log)
- **Active journal bypass — corrected before freeze.** An early draft could declare a same-version install complete before consulting the bindir’s lock. The final code checks the existing pair only after acquiring the directory reservation on writable prefixes. A read-only prefix can take the no-op path if there is no outstanding journal. During a controlled overlap, a forced install held the reservation while its local download was paused. A second installer asked for the same reported version, exited nonzero, left the old pair untouched, and preserved the owner’s journal. The owner then published both expected new files. [Concurrent install](installer-active-reservation.json) Both binaries must report the requested version to skip installation. Two different usable builds can report the same version, so the no-op checks versions only. File replacement is atomic for each pathname. A process that reads both paths during publication can see a mixed pair. SIGKILL or host power loss between renames can leave a mixed pair and a journal requiring operator recovery. [Installer transaction regressions](../../../../../scripts/tests/test_install_transaction.py) · [Operator instructions](../../../../../docs/install.md)

## Release packaging

- **Output collision — corrected before freeze.** The initial packager could overwrite existing checksum files and subsequently fail to publish the corresponding archive. The corrected helper stages all bytes, creates the two sidecars with exclusive same-filesystem hard links, and publishes the archive last. An ordinary conflict preserves existing outputs and removes only the new links claimed by the failed process. Two independent same-basename publishers with different ordinary fixture inputs produced one successful complete bundle. Both checksums and both regular archive members matched the same winning process. Abrupt termination before the final link can leave staging or a checksum file in the workspace. [Packager](../../../../../scripts/package-native-release.py) · [Concurrent publication evidence](packaging-output-ownership.json)
- The helper emits six fixed file paths inside a single release directory with normalized USTAR metadata, numeric uid/gid zero, fixed modes and member order, and a source-derived timestamp. It suppresses gzip filename metadata. Each input file is opened with final-component no-follow and nonblocking flags and checked as a regular file on the opened descriptor. A legitimate regular input can have more than one filesystem hard link. Its bytes were copied to one regular tar member and no other source filename was included. The build workspace and its parent directories remain trusted. The hosted workflow references this same helper. These checks apply to deterministic packaging of fixed inputs with the same compression implementation. Independent compiler reproducibility and hosted provenance remain separate.

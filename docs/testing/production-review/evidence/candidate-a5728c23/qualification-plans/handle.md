## Separate binary criteria

1. **Shape restoration:** follow-up handle size is at most the matched c19 144-byte reference, on the same x86-64 target/profile/toolchain, with exact metadata chain and archived release binary. Compare 296b 208 B, baseline, and new values explicitly. If not at most reference, fail this engineering target; if measurement binding is missing, mark not evidenced. This is an optimization criterion, not a frozen project rubric change. A different architecture/build is a separate measurement, not silently comparable.
2. **Ordinary plugin clone behavior:** an actual signed standard WIT compute plugin works before/after cloning, under unchanged local and remote normal CLI paths. Inspect source to establish that ordinary `PluginPre` representation and output/error handling remain correct. Exercise output bytes, effective tier, identity, memory/timeout enforcement, concurrent invocations and drop of an independent clone. Compare observable behavior with 296b; verify no extra instantiation or registry lifetime accident attributable to the storage change. An identical CLI checksum alone is insufficient.
3. **Libtest clone and verified pin lifetime:** use actual signed trusted WASI CLI suites, with independently hashed artifact and manifest. Clone the loaded representation and verify matching pin works for discovery, exact run and retry. Test both component-only and manifest-only differences, old pin after unload/reload, same-ID swap between list/run and before retry, and unload while an invocation is admitted. Admitted work retains original verified bytes/pin until completion; after drain the old pin fails and the new pin succeeds; no wrong guest execution. Confirm identity is host-authored specifically for the verified libtest ABI, not generic plugin output; no guest-output provenance or host-attestation claim. Include unpinned standalone `from_libtest` if still public and show a pinned request refuses it. Retain worker IDs, pin values, full response/exit, completion/ack ordering, binary hashes and before/after source ID.
4. **Boundary and compatibility:** inspect actual frozen diff for changes to compute RPC serialization, wire discriminants/compatibility, world dispatch, peer trust, signature/publisher verification and authorization; no such changes may be smuggled into a storage-only claim.

# Independent scoped review: route refresh and compact libtest handle

Reviewed by `/root/qa` on 27 November 2026 UTC at commit `a5728c230e5049556b806cae8597fe823dd67987`, source `sha256:a43296d252b79d7a0762861de1251b0e2e77fde20af2ea5dd43254617376fce5`. This is a focused review of the changed route-miss refresh and libtest storage representation, plus fresh signed-suite identity controls and a local publisher incident exercise. It is not a general external audit, host attestation, production key-custody review or independent physical-network qualification.

The reviewed scheduler address book checks current persisted trust before permitting a mapped missing-route refresh; after refresh it looks up the route again and checks trust, peer ID and bound public key before dispatch. Refresh requests share the status owner, coalesce, cool down and have bounded waits; the Tailscale status subprocess is configured to terminate on drop. Present routes do not incur the demand wait. Errors and loss of a route are distinct from authorization. Fresh tests of actual tailnet timing and peer revocation must be assessed separately; local source inspection does not establish physical network behavior.

The ordinary WASI plugin variant retains its precompiled `PluginPre`. The libtest variant now shares one immutable object containing both the precompiled command and the optional verified artifact/manifest identity. Cloning shares that pair; the host checks an expected pin before invocation and emits its identity with captured output. This applies to operator-approved signed `wasi:cli/command@0.2.0` libtest packages and trusted executors. Arbitrary unrelated guest ABIs may return opaque guest-selected JSON; this is not host attestation or guest-proof transcript provenance.

The fresh [14-phase signed identity test](qa-identity.json) verified artifact-only and manifest-only mismatches, swaps after discovery and before a retry, unload and revoke errors, admitted-work drain, post-drain new pin, legacy worker failure and matching controls. Removing the signing key alone does not retroactively unload an already loaded suite; the test records that explicitly. The archive-linked [release layout receipt](handle-layout/integrated-release-layout.json) measures a 136-byte x86-64 `LoadedPlugin` handle using its Cargo fingerprint chain; this is a layout observation, not RSS or latency evidence. Focused host/runtime/scheduler and existing signed pin tests should be evaluated with the full candidate test receipts.

The fresh [publisher incident rehearsal](qa-publisher-incident.json) used disposable keys and the checked local archive: a private report, affected package unload, invocation and old-key reload denial, and recovery with a separate key. It sent no external messages and proves no production disclosure or ceremony. No unresolved High or Critical issue was identified in the reviewed change under the assumptions and limits above.

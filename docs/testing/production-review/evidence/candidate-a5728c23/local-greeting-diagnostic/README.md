The common client used CPUs 0–1, daemons used CPUs 2–3, and the cgroup reported no throttled periods. The one-second process monitor saw one Python process above its threshold; it cannot identify activity confined between samples. The retained single-thread Tokio RPC client and the absence of a companion network peer distinguish this diagnostic from the primary two-thread, two-daemon benchmark. A preliminary scratch configuration failed policy validation before any work was sampled. The authorized correction selected supported single-node mode and preserved the schedule and oracle.

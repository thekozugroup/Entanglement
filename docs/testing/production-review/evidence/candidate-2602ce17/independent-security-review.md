## Residual risk and boundaries

- **Mutable references and publisher changes.** A registry tag and its signed package identify content and publisher at retrieval time. A trusted mirror can still serve an older legitimately signed package under a mutable tag. A user who needs a particular identity can supply `--expect-id`. Immutable content requires a digest pin. Publisher removal blocks subsequent loads. Containment of an already loaded component requires unloading it on each affected node. The recorded incident exercise demonstrates this sequence on an isolated Linux node. [Install policy](../../../../../crates/entangle-cli/src/cmd/distribution.rs) · [Publisher containment rehearsal](publisher-incident-exercise.md)
- **Inference trust.** The worker signature attributes response bytes to that worker. Model inventory is a claim by the selected local service. The tests used controlled protocol fixtures. Model correctness and host-level isolation of the separate service remain outside that evidence. A different signed Wasm plugin remains usable if the model backend is unavailable. [Operational scope](../../../../../docs/operations.md) · [Inference fixture transcript](inference-compatibility/inference-compatibility.log)
- **Coverage exclusions.** Independent release and peer-authorization review, dependency scanning and the publisher rehearsal provide separate evidence. This review did not assess new cryptographic primitives, OS/Wasmtime or GPU internals, actual foundation models, native agent-host execution, distributed revocation gossip, legacy one-shot policy-envelope integrity, hosted repository permissions, macOS hardware, physical WAN conditions, or human incident-response performance. Production release approval requires the remaining gates and their own evidence.

**Reviewer conclusion.** The narrowly scoped controls above are supported by candidate code and the cited test results. The direct-load availability finding remains open for this revision. This review and the local disclosure rehearsal should be assessed together with the separate release/peer review, without treating them as blanket project assurance.

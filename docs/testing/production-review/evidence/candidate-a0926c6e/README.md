## Dispatch and distributed test changes

When ordinary one-shot work cannot be placed, the daemon can now request fresh capabilities from explicitly configured, currently trusted peers. An allowlisted job contacts only its allowed peers. If a worker can execute the task, the scheduler selects once more before execution using the remaining time. This handles the interval between a signed worker loading a plugin and the next 15-second inventory poll. Concurrent requests share peer queries. The regular and expedited lanes each permit eight concurrent queries. The expedited query deadline is two seconds and the submission waits at most 2.5 seconds within its original deadline. [Operator contract](../../../../operations.md) · [Daemon implementation](../../../../../crates/entangle-bin/src/capabilities.rs)

The first implementation blocked unauthorized work but changed the error for the trusted-executor fallback. A full workspace run caught the change and disqualified that build. The corrected candidate preserves the E0303 integrity error and handles the empty allowlist before requesting a refresh. It also fixes the standalone dependency-audit setup for a historical benchmark by supplying the project's license and isolating its Cargo workspace. The audit still enumerates all 16 lockfiles. [Disqualified candidate](../candidate-8e07cc25/iteration-verdict.md) · [Dependency audit](dependencies.json)

The distributed Rust test runner now preserves a target-reported skip along with its worker and captured output. Discovery-time ignores consume zero attempts. A target that skips after dispatch records that attempt. Retry history keeps any earlier assertion failure or execution error visible. [Sharder regression tests](python-runner-tests.json)

The resource monitor recorded 96 samples and observed zero build processes.
